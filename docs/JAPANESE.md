# Japanese (BPEJ)

**Status: experimental, not tested on a console.** `tools/localize_japanese.py`
stages the Japanese game data from the player's ROM: texts, graphics, credits,
the Easy Chat id lists and `GAME_LANGUAGE`. Patches 0057–0061, 0063, 0064,
0066–0068, 0070–0079 and 0083 make a Japanese build behave like the Japanese game, and
`tools/bootstrap.py`, the builders, the web builder and the release scripts
accept that ROM ([Building the Japanese game](#building-the-japanese-game)).
Some screens and features are still open ([Code changes a Japanese build needs](#code-changes-a-japanese-build-needs)).
This page describes what the manifest covers, how it was made and checked, how
to build the game and what is left.

The supported cartridge is **Pocket Monsters Emerald (Japan, BPEJ)**,
SHA-1 `d7cf8f156ba9c455d164e1ea780a6bf1945465c2` (No-Intro).

## The manifest

`tools/locales/japanese.json.gz` has the Italian manifest's schema: positions in
the patched tree, offsets and sizes in the Japanese ROM, and no game text or
graphics. `tools/locales/japanese-symbols.s.gz` holds the addresses and sizes of
the four Easy Chat id lists and of the staged graphics, nothing else.

### Texts

| Source texts | Count |
|---|---|
| Mapped | 19,210 |
| Absent from the Japanese game | 150 |
| Japanese layout differs (needs code, not data) | 42 |
| Not mapped (the Italian manifest's own gap: a TM generated by a macro) | 1 |
| **Total** | **19,403** |

The total is the Italian manifest's 19,347 texts, its one unmapped entry, and 55
vanilla texts that no locale manifest covers (see below). Every text left out is
listed in the manifest's `unmapped_source_texts` with its reason.

Conventions that differ from the Italian manifest:

- braille ranges include the 6-byte `brailleformat` header;
- kind `c_eos` is a Japanese string stored without its terminator (the Pokédex
  categories, a fixed 6-byte field padded with 0x00); staging appends the 0xFF.

Besides the source texts, the manifest stages tables that a code patch of this
repository declares empty for the Japanese build: the naming screen's two R-button
tables (0074), the Union Room chat's R-button table and Latin page title (0075). The
keyboards' rows of text (0074–0076) and the Easy Chat word lists
by letter, which the Japanese ROM files by kana row (0076), are source texts whose
Japanese layout a code patch reads.

### Graphics

The English build includes 7,873 graphics files (`graphics/` and
`data/tilesets/`: tiles, tilemaps, palettes, fonts, as built, which are the
English ROM's bytes). 7,662 of them have an identical copy in the Japanese ROM.
The other 211:

| English graphics that differ in Japanese | Count |
|---|---|
| Same size and layout, staged | 76 |
| Staged with a code patch of this repository (0071–0076, 0083) | 36 |
| Another size or layout: need code, stay English (`graphics_layout_differs`) | 61 |
| No Japanese counterpart: the five Latin fonts and `berry_fix/text.gbapal` (`graphics_skipped`) | 6 |
| No Japanese counterpart: the Trainer Hill mode floors' maps (`floors_skipped`) | 32 |

Staging also writes 19 graphics that are identical in both ROMs (chosen from
the Italian manifest's list before this inventory), 131 in all, 86 of them
LZ77 streams that staging also decompresses. Among them are
`fonts/normal.hwjpnfont` (every glyph one pixel row higher than the decomp's
copy), `fonts/short.fwjpnfont` (one glyph differs) and
`fonts/braille.fwjpnfont` (the Japanese braille cells for the kana codes the
staged braille texts use); with 0074 the naming screen's tiles (the dakuten and
handakuten keys), keyboard tilemaps, page swap frame and full-width underscore,
with 0075 the Union Room chat's keyboard tiles and tilemap, and with 0076 Easy
Chat's rectangle cursor (whole rectangles instead of mirrored halves) and window
(the footer's labels are tiles). The port's `italian_the_end.bin.lz` is skipped
too: the Japanese credits draw "THE END" from the same letter maps and tiles as
the English game.

The title screen (patch 0083) has the Japanese logo: 22x7 tiles in five
palettes (the English one 14), an affine map of 32x9 entries, 16 pixels from
the left edge instead of 29, sliding left as well as up; the clouds' map uses
palette 5. The version banner (0073, 0083) comes down to y 48 at x 162 and
210, its right half a 32x32 sprite.

Graphics that need code, with what differs:

- `battle_frontier/tourney_buttons`: the sprite sheet is 0x400 bytes, not 0x600;
- `contest/nextturn`: the four sprite sheets are 0xA0 bytes, not 0x100;
- `summary_screen/tiles` and its page tilemaps (`page_*`, `effect_*`): 217
  tiles instead of 240, laid out differently from tile 96 on (where the code
  takes its EXP and HP bar tiles); the two move-effect windows are 9x7 cells one
  column right, not 10x7, and the narrower move selector (`move_select`) is
  placed by code;
- `pokedex/menu`: another tile layout, every Pokédex screen tilemap differs
  (`start_menu_*`, `list*`, `info_screen`, `cry_screen`, `size_screen`,
  `screen_select_bar_*`), and the window positions are in code;
- `pokenav/condition/graph` and `pokeblock/use_screen/graph` (with their
  tilemaps and `nature.gbapal`): 3872 and 4000 bytes instead of 6656;
- `naming_screen/cursor` and `cursor_squished`: 0x80 bytes instead of 0xA0
  (the keyboards themselves are staged with 0074–0076);
- `bag/check_berry` and `bag/berry_tag.bin`: the berry tag is laid out
  differently (158 tilemap cells), so the window templates need checking;
- `slot_machine/menu`, `menu.bin` and `info_box.bin`: the Japanese code loads
  0x1D20 bytes of tiles, the decomp 0x2200;
- `frontier_pass/cancel*.bin`: 12 tilemap cells, not 18;
- `berry_fix/*` (12 files, same sizes): the Japanese berry program's screens
  have their text drawn into the images, the decomp prints it in windows;
- frames that go with the Japanese window templates (code), which are
  narrower or elsewhere: `battle_interface/textbox` and `textbox_map` (action
  menu x2 w15, the decomp's x1 w14; the move, PP and type windows),
  `bag/menu`, `menu.bin` and `menu_pyramid.bin` (description window x1 w12,
  not x0 w14), `pokenav/message.bin` (x4 w22, not x3 w24),
  `pokenav/ribbons/summary_bg.bin` (name window w12, not w13),
  `battle_frontier/factory_screen/menu.bin`,
  `battle_frontier/tourney_info_card` and its tilemap, and the
  `wallclock/clock` tiles and screens (corner button window 4 tiles wide, not 6).

### Credits, Trainer Hill, Easy Chat, language

- **Credits.** 45 pages of 5 entries (55 in the other languages); staging
  rebuilds `src/data/credits.h` from the ROM's credits table, as the Italian
  script does. Patch 0070 shows each page for 156 frames, as the Japanese ROM
  does, instead of 115, so that the credits still end with their music.
- **Trainer Hill.** The Japanese ROM has no counterpart of the four built-in
  modes (Normal, Variety, Unique, Expert): it has one challenge of two floors,
  the decomp's unused `sChallenge_JPDefault`/`sFloors_JPDefault`, whose data
  equals the decomp's but with another trainer record layout (944-byte floors).
  The four tables stay English (`floors_skipped`). Patch 0063 runs that challenge
  from the decomp's own data: compiled and converted to the 944-byte layout, the
  header, both floors and their mazes equal the ROM's (0x5faf38), so nothing is
  staged.
- **Easy Chat id lists.** The four move and Pokémon lists that
  `tools/locale_lists.py` reorders are at ROM offsets 0x574584, 0x57861c,
  0x578750 and 0x578b1c (the groups table's slots 0, 18, 19 and 21), with the
  decomp's ids in kana order; `japanese-symbols.s.gz` names them. The keyboard's
  45 word lists (`gEasyChatWordsByLetterPointers` at 0x579d04: the others, then
  あ to わ by kana row, dakuten under the plain kana) go into the decomp's 45
  lists in order: Others, A–Z for あ to は, and the unused Japanese ones for ひ
  to わ.
- **Language.** Staging sets `GAME_LANGUAGE` to `LANGUAGE_JAPANESE` in
  `include/constants/global.h`, like the other locales.

## How it was made and checked

- **Event scripts.** The Japanese ROM keeps the decomp's map table (34 groups,
  518 maps), its script files in the same order and the same script commands.
  The bytes between two texts are script code, which does not depend on the
  language, so the Italian layout predicts each Japanese text from its neighbour.
  Placements are tied to identity evidence: per-map text counts, trainer IDs,
  C pointer tables and the Japanese script commands that reference each text.
- **Tables** (species, moves, items, Pokédex, trainers, Easy Chat and others)
  are found through the ROM header at 0x100 and checked against their records'
  other fields (IDs, prices, heights, team lists).
- **Strings in C code** follow each C file's data order and are tied to pointer
  tables and code references.
- **Graphics.** Every LZ77 stream the ROM points to was decompressed; 4,129 of
  the decomp's 4,324 compressed assets match one byte for byte and anchor the
  rest. Every graphics file the English build includes was then looked up in
  the Japanese ROM (raw, compressed, and decompressed against every stream).
  Each one without a copy is tied to the code or table that loads it: sprite
  sheets with the decomp's size and tag, literal pools of the Japanese function
  that matches the decomp's (from a matching English build) or that also hold
  the anchored tilemaps and palettes the decomp loads with it, and tables with
  the same slots. Every staged asset has the English size (or the size its
  patch expects) and, where it goes with tilemaps, those are identical or staged
  too; a tilemap whose Japanese frames go with other window templates stays
  English. Differences were checked tile by tile, by rendering the tiles and,
  for the reachable screens (title, bag, summary, PokéNav), in an emulator
  against the cartridge: the title sequence of a scratch GBA build matches the
  cartridge pixel for pixel.
- **Credits, floors, lists** were read from the code that uses them (page count,
  page delay, the Trainer Hill load, the Easy Chat groups table).
- Every pair was read in both languages. A held-out check (trainer-ID links
  hidden from the mapping) placed 678 trainer texts, all correctly.
- The manifest was checked for source hashes, ROM ranges, terminators (`_()`
  appends one, `__()` none), braille headers, graphics streams and sizes, and a
  staging dry run of `tools/localize_japanese.py`. All 320 C units of the staged
  tree, compiled with a host compiler as Japanese, show no new errors against the
  English tree.

The working evidence quotes ROM text, so it stays out of the repository.

## Building the Japanese game

From a dump of your own cartridge (the SHA-1 above; a `.zip` holding it or a
trimmed dump is accepted too), in a shell with devkitPro, a host compiler and
Python ([DEVELOPMENT.md](DEVELOPMENT.md)):

```sh
python tools/bootstrap.py --make --japanese-rom "/path/to/Pocket Monsters - Emerald (Japan).gba"
cd build/upstream/3ds_port
make release pak PYTHON=python3
```

Copy `dist/Emerald3DS.3dsx`, `dist/Emerald3DS.smdh` and `build/emerald3ds.pak`
to `/3ds/emerald3ds/` on the SD card. (`make` alone, without `release pak`,
builds the development `emerald3ds.3dsx` with the data embedded.)

- `--japanese-rom` works like `--spanish-rom`, `--french-rom` and
  `--italian-rom`: the tree is reset to the pinned commit and patched, `make
  tools` and `make generated` run, then `tools/localize_japanese.py --tree
  build/upstream --rom ROM` stages what the Japanese manifest maps from the ROM,
  and `--make` builds the 3DSX. Without `--make` it stops after staging, for
  inspection. Every later run resets the tree again, and a change of language
  (back to English included) also deletes `3ds_port/build`, `3ds_port/romfs`
  and the staged art, so nothing of the other language is reused.
- `make pak` writes the fingerprint of the ROM of the compiled
  `GAME_LANGUAGE` into the pack (`LANGUAGE_JAPANESE`: BPEJ), and a Japanese
  executable accepts only a pack made from the Japanese ROM
  (`3ds_port/src/3ds_data.c`).
- **Follower speech.** HeartGold/SoulSilver's Japanese texts are pinned in
  `builder/emerald3ds_builder/followers_sources.py`
  (`corpus/HeartGoldSoulSilver/ja-Hrkt_msg.txt` of the pinned poke-corpus,
  kana only). Their follower messages are bank 258, the same 759 messages in
  the same order as the other languages' bank 265. They become
  `followers/text/ja.bin` in the Japanese character set (the kana of
  `charmap.txt`'s Japanese section, 0x00 the full-width space; HGSS's line
  breaks become spaces, where the game wraps the text), which a Japanese
  build reads. The builders fetch the ROM's language only. A tree's own pack
  has followers only when the RomFS has them, as for every language: before
  `make release pak`, `python ../builder/emerald3ds_builder/followers.py --out
  romfs --language ja` fetches the sprites and the Japanese texts (or
  `FOLLOWERS_SRC` points the Makefile at a local copy).
- **Builders and releases.** The builder (window and command line) and the
  web builder recognise the dump and build from it when the release has a
  Japanese variant, `payload/ja/` (`Emerald3DS-ja.3dsx` among the release
  assets): `tools/build_release.py --japanese-rom ROM`
  ([RELEASING.md](RELEASING.md)). That variant's recipe takes its symbol hints
  from `build/japanese-reference.s`, which staging writes from
  `tools/locales/japanese-symbols.s.gz`; that file names only the staged
  graphics and the four Easy Chat lists, so the Japanese recipe has far fewer
  hints than the other languages'.

## Code changes a Japanese build needs

Done in this repository, marked *done* below: patches 0057–0061, 0063, 0064 and
0066 (item 1, item 2, item 4 but the Pokédex page, item 5 but the bard and the
credits' scene pages, item 7), patches 0070–0076 and 0083 (credits page delay,
contest results title bar, menu info icons, title screen version logo palettes,
the naming screen's, the Union Room chat's and Easy Chat's keyboards, title
screen logo layout), patches 0067, 0068 and 0077–0079 (item 9), all behind
`GAME_LANGUAGE == LANGUAGE_JAPANESE`, the port UI (3) and the integration (8).
The other items are open.

1. **Engine text.** Text printers start in Latin glyphs, and the international
   code treats Japanese as the foreign language: `GetBoxMonData` wraps a Japanese
   nickname in switch-to-Japanese/back-to-Latin codes, `ConvertInternationalString`
   pads Japanese names, and so on (about 70 `LANGUAGE_JAPANESE` and 40
   `GAME_LANGUAGE` sites). The Latin fonts have no Japanese counterpart.
   *Done* (0057, 0058): printers and `GetStringWidth` start in the Japanese
   glyphs with the Japanese ROM's font metrics; `IsForeignScriptLanguage`
   (`string_util.h`) is false, so no name is wrapped or padded, as in that ROM,
   which shows other games' Latin names in its own full-width Latin glyphs;
   `IsForeignGameLanguage` keeps the Latin-script games out of the Union Room
   and the trainer records.
2. **Names and keyboards.** Player and Pokémon names of 5 characters (*done*,
   0059) and Walda's phrase of 12 (*done*, 0064: as in that ROM, any 12
   characters, each one's code minus 1 giving 6 bits of the wallpaper data, with
   no letter table and no check bits; the save keeps the 15-character buffer).
   *Done* (0074), checked against the cartridge in an emulator: the
   naming screen's keyboard. Three pages of 19 keys a row, hiragana, katakana
   and a Latin page (letters, digits, symbols), their key rows staged as the
   `gText_NamingScreenKeyboard_*` texts, which are also what a key inserts; the
   player's name and Walda's phrase start on hiragana, Pokémon and box names on
   katakana. The dakuten and handakuten keys, and R (`゛゜大小`: the next form of
   the last character, from two staged tables), change the last character.
   Characters sit 10 pixels apart, the page labels かな and カナ are two tiles,
   and Walda's phrase takes 12 characters, as in that ROM. *Done* (0076), also
   checked in an emulator: Easy Chat's keyboard. Its letter mode picks words by
   kana row (あいうえお なにぬねの やゆよ わ / かきくけこ はひふへほ そのた / …)
   from 45 lists instead of 27, group names and words are in three columns, and
   the rectangle cursor is one sprite of the Japanese graphics. Its main screen
   too: phrases of 3 words a row (3x2 and 3x3 instead of 2x3 and 2x5) in the
   Japanese frames, the words run on a tile a character, and the footer is the
   Japanese window graphics. *Done* (0075), checked in an emulator with the link
   step skipped: the Union Room chat's keyboard. Pages of hiragana, katakana,
   Latin letters and digits (the `gText_EmptyTextInput*` rows), symbols and the
   registered texts; R gives the last character its next form from a staged
   table, with a hiragana, katakana or Latin label; keys, chat lines and the text
   typed are in the small font at the Japanese spacing, and the chat's graphics
   are staged. Open: the
   chat's received lines are not checked on screen yet (they need a link).
3. **Port UI** (done). The bottom screen and the HD battle box draw both glyph
   sets (`CtrLocale_Glyph`, `3ds_bottom_ui.c`, `3ds_battle_hud.c`), and every
   `CTR_TEXT` has its Japanese label: kana only, in the game's own words where
   it has them (`せってい`, `とじる`, the bag pockets, `いりょく`/`めいちゅう`),
   each checked against its space at 8 pixels a glyph. Console texts stay ASCII.
4. **Text built in code.** The trade question is two pieces joined around both
   Pokémon names; the Pokédex appends the word for Pokémon to the category with
   no space; the contest "Appeal no. X" lines have no number; mail puts the
   sender after the name; the diploma prints the player name and Pokédex type
   separately; two Lilycove Lady texts use other placeholders; Battle Pyramid
   arrows are a control code. *Done* (0061): the five built lines follow the
   Japanese ROM's code, mail with its layout and signature window; the Lilycove
   Lady texts use the same placeholders, only more or fewer times, and the
   Pyramid's escape-code arrows draw as they are in Japanese glyphs, so neither
   needs code. The Pokédex's metric units and its cry and size lines: item 9.
5. **Content and logic.** Japanese Trainer Hill has no "closed until the game is
   cleared" state and only its two-floor challenge; only the international game
   refuses record mixing with a Japanese game; the bard sings each kana through a
   vowel table instead of per-word phonemes; apprentices have a Japanese name
   only. The Japanese credits change scenes at their own pages (5, 9, 14, 20, 25,
   30, 37, 42) where the decomp spaces them by `PAGE_COUNT / 9`. *Done* (0060):
   no closed state and no refusal; the wild/foe prefix stays in front of the
   name (0058); apprentices need no code (`GetApprenticeNameInLanguage` gives
   the Japanese name, slot 0). *Done* (0063): the two-floor challenge, which the
   attendant starts without asking for a tag match type; the challenge id in the
   save (`trainerHill.unused`) keeps one best time, reset with the prize when the
   challenge changes (the international game keeps a time per mode instead), and
   the time board lists each floor's two trainers above the clear time, as that
   ROM does. The e-Reader challenges that ROM can also load are not supported (the
   port cannot scan cards); the time board's window keeps the international width
   (26 tiles; the Japanese one is 27, its text fits in both). Open, as read in
   that ROM's code:
   - *The bard.* Its song task walks the printed lyrics one character at a
     time. A table indexed by character code (0x5d2b4c, `{s16 song, u16
     volume}`) gives each kana one of the sounds SE_A–SE_O and SE_N (25–30,
     still in the decomp's song table), っ and punctuation a rest, ー and ⋯ a
     held note; each note lasts 16 frames, and its pitch is the next value of
     the `sPitchTables` row chosen by the word's length in kana and its Easy
     Chat id (`(word & 3) + ((word >> 3) & 1)`). Spaces, line breaks and
     control codes pause. The decomp's per-word phoneme templates
     (`src/data/bard_music/`, `BardSing`) have no counterpart there. Doing it
     means a Japanese song task and staging that table; the Japanese build
     sings with the international code.
   - *The credits' scene pages.* That ROM's `CheckChangeScene` changes scenes
     at pages 5, 9, 14, 20, 25, 30, 37 and 42 and also cues the bike scenes at
     pages 1, 22 and 35, where the decomp uses frame timers, and its Pokémon
     interludes show 56 Pokémon, one every 64 frames (71 every 50 frames in the
     decomp). The Japanese build keeps the decomp's spacing (pages 5, 10, …, 40).
6. **Screens with another layout:** the graphics listed above.
7. **Port additions** that need their own Japanese text (*done*, 0066): the
   Exp. Share team message, てもちの　ほかの　ポケモンも／けいけんちを　もらった！
   (the ROM's てもちの ポケモン and its own line for one Pokémon's EXP; 14 and 12
   glyphs in the 26-tile battle message box), and the summary screen's category
   label, しゅるい (the word the Battle Palace sorts moves by; 32 pixels left of the
   icon, like いりょく and めいちゅう below it).
8. **Integration** (done): builder and web builder acceptance of BPEJ, the ROM
   guard in `3ds_data.c`, `bootstrap.py --japanese-rom`, the release's
   `payload/ja/` and Japanese follower texts. Open: a fuller reference symbol
   file for the release recipe.
9. **Numbers, fields and lines the code builds.** Checked screen by screen
   against the cartridge (main menu, start menu, party, summary, bag, Pokédex,
   PokéNav, Pokéblock case, trainer card, a wild battle). *Done*:
   - 0067: the CONTINUE window fills the `{STR_VAR_n}` of its Japanese texts
     (the international code left them unset and hung there with a save); the
     start menu's save information has that ROM's layout and counter words.
   - 0068: `CHAR_SPACER` (0x77, a kana in Japanese) is the space, so padded
     numbers no longer show stray kana; the fields the 8-pixel digits overflowed
     take the Japanese ROM's layout: summary stats, Exp. Points and power and
     accuracy, the party boxes' HP, the Pokéblock feel, the PokéNav ribbon list,
     and the battle's action and move menus (that ROM's window and text tables,
     cursors and move-type label).
   - 0077: of the texts whose placeholders differ from the English ones, the
     code-filled ones: the Exp. Points message (the Japanese ROM has no third
     battle buffer) and the trainer card's back (name, link wins and losses).
     The others need nothing: the map texts that gained `{STR_VAR_1}` follow a
     `GetPlayerBigGuyGirlString`/`GetRivalSonDaughterString` both games call,
     the apprentice, Battle Dome, shop (TM move) and link player-count texts
     use vars the shared code fills, the two contest texts are in an unused
     table, and the appeal number and diploma were done in 0061.
   - 0078: the Pokédex in meters and kilograms (that ROM's unit templates and
     `PrintDecimalNum`), its cry and size lines in Japanese word order; the
     Lotad/Seedot size records in centimeters; the decimal separator 0xB8.
   - 0079: the summary's portrait panel and text positions, yes/no boxes, the
     party action menu's width, the Match Call list's columns.

   Still different, by design or open: the Japanese glyphs sit a row higher,
   and that ROM prints most texts a pixel lower than the international code
   (done only where the screens above were changed); the trainer card's front
   (small-font values, positions); the bag's item menu and the party's message
   windows (sizes); the field message box (the Japanese ROM's is 22 tiles at x 4
   with its own frame code; the 3DS port places this box itself); the GBA
   battle info boxes' numbers (the 3DS HD box draws its own); the PokéNav
   condition search list's lines (`BufferSearchMonListItem`, not compared);

## Findings about the existing locale manifests

- French and Italian braille texts lost their 6-byte header, so the game read
  each braille message 6 bytes in (fixed in an earlier commit).
- 55 vanilla English texts are in no locale manifest: the Sealed Chamber
  braille alphabet panels, 7 Union Room prompts, about 20 Mystery Gift texts,
  8 `strings.c` and 5 `battle_message.c` strings, and a few single texts such as
  `SecretBase_Text_DiscoveredSmallEntrance`. Spanish, French and Italian builds
  show them in English.
- 12 texts are mapped in some locale manifests only (for example 7 Berry Blender
  strings in the Italian and Spanish manifests but not the French one).
- The Italian manifest maps 13 texts that appear in several maps (door signs,
  harbors, cable car) to a single copy, and two graphics to another graphic's
  copy (`pokeblock/use_screen/condition`, `pokenav/ribbons/list_bg`), which is
  harmless where the two are identical.
- About 170 other decomp graphics have no identical copy in the Japanese ROM
  (for example the Pokémon title logo, the Pokédex screen tilemaps and the
  international-only Trainer Hill maps). They are outside the Italian list and
  not mapped.
